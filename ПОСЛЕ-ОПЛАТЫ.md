# venikoff.net — что происходит после оплаты

Файл для коллеги, которая будет дорабатывать тексты и логику после оплаты.
Открывается в Claude Code вместе с репозиторием: он объясняет, что где лежит,
что срабатывает после оплаты и какие фразы видит покупатель.

Общий свод по проекту — в `CLAUDE.md` рядом. Здесь только то, что нужно для работы
с оплатой, ботами и сообщениями.

---

## 1. Коротко о проекте

Цветочный магазин с доставкой **только по Москве**. Бренд **venikoff.net**,
основной цвет — фуксия `#E0178A`.

| что | где |
|---|---|
| Сайт | https://venikoff.net |
| Админка | https://venikoff.net/admin/ (вход по почте владельца) |
| Сервер | VPS Timeweb, Москва, `root@147.45.141.23` |
| База и API | PocketBase 0.40, `127.0.0.1:8090`, служба `venikoff-pb` |
| Веб-сервер | Caddy, сайт из `/opt/venikoff/site`, `/api/*` → PocketBase |

Пароли и ключи в репозитории **не хранятся** — они в базе (настройки) и в
`~/.venikoff/server-credentials` на рабочем компьютере владельца.

### Из чего собрано

| файл | что в нём |
|---|---|
| `index.html` | весь сайт: вёрстка, каталог, корзина, оформление заказа, личный кабинет |
| `admin/index.html` | админка |
| `add/index.html` | отдельная страница загрузки товаров для управляющей |
| `server/pb_hooks/lib/shop.js` | общие функции: каталог, расчёт заказа, **тексты сообщений покупателю**, отправка в Телеграм |
| `server/pb_hooks/lib/pay.js` | CloudPayments: проверка платежа |
| `server/pb_hooks/lib/ms.js` | МойСклад: заказ, платёж, статус |
| `server/pb_hooks/lib/bot.js` | оба Телеграм-бота (служебный и клиентский) |
| `server/pb_hooks/lib/max.js` | мессенджер MAX |
| `server/pb_hooks/pay.pb.js` | ссылка на оплату, проверка оплаты, страница заказа |
| `server/pb_hooks/shop.pb.js` | API магазина + **хук, который шлёт покупателю сообщение о статусе** |
| `server/pb_hooks/ms-status.pb.js` | тянет статус из МоегоСклада раз в минуту |
| `server/pb_hooks/watchdog.pb.js` | сторож: следит за ботами, дублями, зависшими заказами |
| `server/deploy.sh` | выкладка на сервер |

> **Важная особенность PocketBase:** обработчики (`cronAdd`, `routerAdd`, хуки)
> **не видят код верхнего уровня файла**. Всё, что нужно внутри, объявляется
> внутри самого обработчика или подключается через `require` прямо в нём.
> Это не стиль, это ограничение — иначе получите `... is not defined`.

## 2. Цепочка после оплаты, по шагам

### Шаг 1. Покупатель нажимает «Оплатить»

`index.html` → функция `payCard()`.

Сначала спрашиваем сервер, жив ли заказ (заказ мог быть удалён, а браузер помнит
старый — так однажды списались 100 ₽ в никуда). Потом:

```
POST /api/shop/pay-link   { order: <id заказа> }
```

`server/pb_hooks/pay.pb.js` создаёт **платёжную страницу** CloudPayments
(`POST /orders/create`) и возвращает адрес. Браузер уходит туда целиком.

Важно: используется именно страница банка, **не виджет**. У виджета кнопка
«Вернуться в магазин» не срабатывала, и на телефоне он терял управление.

В запросе к банку:
- `InvoiceId` = номер заказа — по нему потом ищем платёж;
- `SuccessRedirectUrl` и `FailRedirectUrl` = `https://venikoff.net/#/order/<код>`.

### Шаг 2. Банк возвращает покупателя на страницу заказа

Адрес вида `venikoff.net/#/order/8EcVWGFhuo`. Код — случайное поле `orders.tg_code`,
в адресе не угадывается.

**Страница заказа — единственное место, где покупатель узнаёт судьбу заказа.**
Она ничего не решает сама: показывает то, что ответил сервер. Пока оплата не
подтвердилась — переспрашивает раз в три секунды около двух минут.

```
GET /api/shop/order/{code}
```

Этот запрос заодно сам дёргает проверку платежа, не дожидаясь ежеминутной.

### Шаг 3. Сервер проверяет платёж

`server/pb_hooks/lib/pay.js` → `checkOrder()`:

1. `POST /v2/payments/find` по `InvoiceId` (номеру заказа);
2. годится статус `Completed` или `Authorized`;
3. если оплачено меньше суммы заказа — не засчитываем;
4. ставим `payment_status = paid`, `payment_id`, `paid_at`;
5. **статус заказа не трогаем** — его ведёт только МойСклад (см. шаг 5).

Дальше:
- владельцу в служебный бот: `💳 Оплачено картой — 2 490 ₽` и следом **полная
  карточка заказа**. До оплаты карточки нет специально: раньше в боте висели
  заказы, к оплате которых покупатель даже не приступал;
- в МойСклад: если заказ там уже есть — переводим в «Принят, Оплачен»
  (`markPaid`), если нет — создаём (`pushOrder`). **Доставка создаётся в
  МоёмСкладе только сейчас, после оплаты; самовывоз — сразу при заказе;**
- создаём входящий платёж (`addPayment`), привязанный к заказу.

Есть ещё `cronAdd("pay-poll")` — раз в минуту добирает «висящие» оплаты за
последние 3 часа. На случай, если покупатель закрыл страницу.

### Шаг 4. Покупателю уходит сообщение

Хук в `server/pb_hooks/shop.pb.js` срабатывает на любое сохранение заказа.
Если статус изменился — вызывает `shop.notifyCustomer()`, а тот пишет
в Телеграм и/или MAX — туда, где покупатель подписан.

**Защита от повторов:** отметка «об этом статусе уже сообщили» лежит в отдельной
табличке `order_notified` (ключ «заказ + статус»). Хранить её полем в самом заказе
нельзя — соседний код сохраняет заказ из копии, прочитанной раньше, и затирает
отметку; покупателю приходило **6 одинаковых** сообщений подряд.

Если сообщение не ушло (Телеграм или MAX ответили ошибкой), владельцу сразу
прилетает `⚠️ Заказ №N: не удалось сообщить покупателю` с именем и телефоном.

### Шаг 5. Статус ведёт МойСклад

`server/pb_hooks/ms-status.pb.js`, раз в минуту: читает состояние заказа
в МоёмСкладе и переводит наш статус. Названия состояний сопоставляются так:

| в МоёмСкладе | у нас | что видит покупатель |
|---|---|---|
| Принят, Оплачен / Подтвержден | `confirmed` | Заказ подтверждён |
| Сборка / Ожидает сборку | `assembling` | Начали собирать |
| Собран / Готов к самовывозу | `photo` | Букет собран |
| Доставляется / Передан службе доставки | `delivering` | В пути |
| Завершен / Доставлен | `done` | Доставлен |
| Отменен | `cancelled` | Отменён |

**Больше никто статус не ставит.** Ни оплата, ни отправка фото. Два источника
перебивали друг друга. Если выключить интеграцию (`ms_enabled`), вернётся
прежнее поведение — чтобы покупатель не остался совсем без вестей.

### Шаг 6. Фото букета

Флорист отправляет фото **ответом** на карточку заказа в служебный бот
`@newbouquet_bot`. Дальше `server/pb_hooks/lib/bot.js`:

1. фото сохраняется у нас (коллекция `order_photos`);
2. уходит покупателю **файлом**, а не ссылкой. Телеграм не может достучаться до
   нашего сервера и на ссылку отвечает «failed to get HTTP URL content».
   В MAX картинка грузится в три шага (см. `mx.sendPhoto`);
3. под фото кнопки `👍 Нравится` / `👎 Поправить`;
4. ответ покупателя пишется в `photo_status` (`approved` / `rework`) и уходит
   владельцу в служебный бот.

В MAX покупатель отвечает **только кнопками**. Свободный текст мы не разбираем:
пересылаем менеджеру вместе с телефоном — отвечает человек.

### Шаг 7. Сторож

`server/pb_hooks/watchdog.pb.js`, раз в 10 минут. Пишет владельцу в служебный бот:

- бот молчит дольше 6 минут (служебный, клиентский, MAX);
- оплачено, но не ушло в МойСклад дольше 15 минут;
- в МоёмСкладе задвоились заказы;
- покупатель не ответил на фото больше двух часов.

Про одну беду сообщает один раз и отдельно сообщает `✅ снова в порядке`.

## 3. Все сообщения покупателю

**Где править:** тексты статусов — `server/pb_hooks/lib/shop.js`, объект
`CUSTOMER_TEXT`. Остальное — `lib/bot.js` (Телеграм) и `lib/max.js` (MAX).
Если правите фразу, которая есть в обоих, — правьте в обоих файлах.

### Вход в личный кабинет

> Готово, {имя}, вы вошли на сайте venikoff.net.
> Здесь будут статусы заказов и фото букета перед доставкой.

> Ссылка устарела. Нажмите «Войти» на сайте ещё раз.

### Подтверждение номера (только Телеграм)

> Чтобы в кабинете были и прошлые заказы, подтвердите номер — нажмите кнопку внизу. Мы увидим тот же номер, что привязан к вашему Телеграму.

> Это чужой номер. Нажмите кнопку «Подтвердить номер» — Телеграм пришлёт ваш собственный.

> Номер подтверждён. Теперь в кабинете видно все ваши заказы, даже сделанные без входа.

### Подписка на заказ

> Заказ №3021 на 2 490 ₽ принят.
> Доставка: сегодня, 17:30–20:30.
> Будем присылать сюда статусы и фото букета.
> Страница заказа: venikoff.net/#/order/…

> Этого заказа уже нет — похоже, ссылка старая. Вы всё равно подключены: сюда придут статусы и фото букета по новым заказам.

### Статусы заказа (`CUSTOMER_TEXT`)

| статус | текст |
|---|---|
| `confirmed` | Заказ №3021 подтверждён. Соберём и пришлём фото перед доставкой. |
| `assembling` | Заказ №3021: начали собирать ваш букет. |
| `photo` | Заказ №3021: букет собран, фото отправим следом.<br>*самовывоз:* Заказ №3021: букет готов, ждём вас сегодня с 17:30. |
| `delivering` | Заказ №3021 в пути. Доставим сегодня, 17:30–20:30.<br>*+ строка «Курьер: …», если поле заполнено в МоёмСкладе* |
| `done` | Заказ №3021 доставлен. Спасибо, что выбрали venikoff.net!<br>*самовывоз:* Заказ №3021 выдан. Спасибо, что выбрали venikoff.net! |
| `cancelled` | Заказ №3021 отменён. Если это ошибка — позвоните нам. |

### Фото букета

Подпись под фото:

> Ваш букет по заказу №3021 готов. Везём сегодня, 17:30–20:30.
> Нравится?
> `[👍 Нравится] [👎 Поправить]`

- 👍 → **Спасибо! Везём ваш букет.**
- 👎 → **Что поправить?** + кнопки: `🎨 Не те цвета`, `🌸 Не те цветы`,
  `📏 Маловат букет`, `🎁 Другая упаковка`, `✍️ Напишу сам`
  *(в MAX вместо последней — `📞 Пусть позвонят`)*
- выбрал причину → **Передали флористу. Пришлём новое фото.**
- «Напишу сам» → **Напишите, что поправить в букете по заказу №3021 [ord:pccrnsyw8mx1koy]**
- прислал текст → **Передали флористу. Пришлём новое фото.**
- в MAX «Пусть позвонят» → **Сейчас вам позвонит наш флорист.**

### Покупатель просто написал боту

> Заказ №3021 — Подтверждён
> Доставка: сегодня, 17:30–20:30
> Сумма: 2 490 ₽ (оплачено)

> Здравствуйте! Это бот магазина venikoff.net. Здесь приходят статусы заказа и фото букета перед доставкой.

### Что стоит поправить (нашли, но пока не трогали)

1. **`[ord:pccrnsyw8mx1koy]`** — техническая метка, а её видит покупатель.
   Нужна, чтобы по ответу найти заказ. Можно убрать: состояние «ждём текст
   правки» уже умеет храниться в самом заказе (`photo_status = "wish"`,
   так сделано в MAX).
2. **«позвоните нам»** — без номера телефона. Стоит подставлять телефон магазина
   из настроек.
3. **«букет собран, фото отправим следом»** — а следом приходит само фото.
   Возможно, сообщение лишнее.
4. Везде сухое «venikoff.net». На сайте голос другой — «Букет, а не веник»,
   «оптовые цены в розницу», «цветы напрямую от производителей».

## 4. Грабли — это уже чинили, не повторяйте

- **Не сохраняйте запись дважды подряд.** Хук уведомления сравнивает статус с тем,
  каким запись была при загрузке: на втором сохранении он снова считает статус
  только что изменившимся, и покупателю уходит второе такое же сообщение.
- **Отметки-флаги в самой записи затираются.** Если пишете флаг запросом
  (`UPDATE ... WHERE id`), соседнее `app.save(o)` из прочитанной раньше копии
  вернёт старое значение. Такие отметки держим в отдельных табличках:
  `order_notified` (о чём сообщили) и `order_locks` (что уже делаем).
- **Заказ в МойСклад отправляем под замком.** Проверки `if (o.get("ms_id"))` мало:
  две одновременные проверки оплаты обе видели пустое поле и создавали по заказу.
  Так задвоились №3014 и №3020, и МойСклад потом не давал их сохранить —
  «нарушено ограничение уникальности параметра name».
- **Фото покупателю — файлом, не ссылкой.** Телеграм до нашего сервера не достучится.
- **Нельзя открывать оплату по заказу из памяти браузера** — заказ мог быть удалён,
  деньги спишутся в никуда. Перед оплатой спрашиваем сервер, жив ли заказ.
- **Интервал доставки проверяем правилами, а не совпадением строки со списком** —
  браузер и сервер считают время в разные секунды.
- **В `pattern` у телефона скобки и дефис экранируются** (`[0-9+\-\(\) ]`), иначе
  в новых браузерах `checkValidity()` падает и проверка формы молча отключается.
- **`\b` после кириллицы в JS не работает** (кириллица — не `\w`). Границы слов
  пишем как `(^|[^а-я])`.

## 5. Как выложить изменения

```sh
sh server/deploy.sh   # сайт, админка, серверные обработчики, миграции
git push              # обновит и запасную копию на GitHub Pages
```

`deploy.sh` сам проверяет, что сайт и каталог отвечают 200.

Перед выкладкой **проверяйте вёрстку в режиме телефона (375 px)** — покупатели
почти все с телефонов.

### Как посмотреть, что на сервере

```sh
ssh -i ~/.ssh/venikoff_ed25519 root@147.45.141.23
journalctl -u venikoff-pb -f          # журнал
sqlite3 /opt/venikoff/pb/pb_data/data.db "select number,status,payment_status from orders order by created desc limit 5;"
```

Служебная панель PocketBase снаружи закрыта, только через туннель:

```sh
ssh -i ~/.ssh/venikoff_ed25519 -L 8090:127.0.0.1:8090 root@147.45.141.23
# затем открыть http://127.0.0.1:8090/_/
```

### Чего делать не нужно

- Не заводите вторую точку правды для статуса заказа — его ведёт МойСклад.
- Не пишите ключи и пароли в репозиторий: они живут в настройках в базе.
- Персональные данные покупателей по 152-ФЗ хранятся только на сервере в России —
  не выгружайте их в чужие сервисы.
